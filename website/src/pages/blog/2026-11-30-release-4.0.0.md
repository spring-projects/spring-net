Dear Spring Community,

We are pleased to announce that Spring .NET 4.0.0 is now available.

[Download](/download) | [Support](http://www.springsource.com/services/enterprisesupport) | [Documentation](/documentation)

### Breaking Changes

The full list, with migration notes, is in [BreakingChanges.txt](https://github.com/spring-projects/spring-net/blob/main/BreakingChanges.txt).

* The assemblies' version is 4.0.0.0, so code compiled against 3.x has to be recompiled
* .NET Framework 4.7.2 is the lowest supported .NET Framework (was 4.6.2)
* The System.Configuration.ConfigurationManager floor is 8.0.1, which drops the vulnerable System.Drawing.Common 4.7.0
* Spring.Services, Spring.Messaging.Ems, Spring.Web.Extensions, Spring.Template.Velocity and Spring.Template.Velocity.Castle are removed, along with the ASMX web service exporter in Spring.Web
* Dependency floors were raised (Microsoft.Extensions.Logging.Abstractions 8.0.3, NHibernate 5.7.1, Quartz 3.22.9, ASP.NET MVC and Web API 5.3.0), which needs binding redirects on .NET Framework
* On .NET Framework, Spring.Core no longer depends on the ConfigurationManager, CodeDom and Registry packages, and Spring.Messaging drops Experimental.System.Messaging.Signed
* Spring.Aop no longer depends on Antlr3.Runtime
* The libraries have a net10.0 build, code access security and partial-trust hosting are gone, and legacy serialization is obsolete (SYSLIB0051) on .NET 10
* Spring.Testing.NUnit requires NUnit 5 and targets net10.0 and net472, and Spring.Testing.Microsoft requires MSTest 4.5.2
* LogExceptionHandler.ActionExpressionText is the message expression only, not a `#log.<Level>(...)` call
* The expression language is parsed by a generated Parlot parser, so the embedded ANTLR 2 types and most of SpringAST's inherited API are gone
* AbstractObjectFactory.RegisterDisposableObject is obsolete and does nothing
* Exception handler templates are copied for each DSL statement, and AbstractExceptionHandler is ICloneable
* Spring.Scheduling.Quartz3 is maintenance-only, and the new Spring.Scheduling.Quartz4 package takes over for Quartz.NET 4.x

### New Feature Highlights

* .NET 10 builds of the libraries (`net10.0` next to `netstandard2.0` and `net472`)
* A new expression parser, generated with Parlot at build time instead of the ANTLR 2 runtime, with no runtime dependency on Parlot and with the same trees (#375)
* New Spring.Scheduling.Quartz4 package for Quartz.NET 4.x (#399)
* The test suite runs on NUnit 5 and Microsoft.Testing.Platform, and the SQL Server and ActiveMQ integration tests start their own Testcontainers
* Memory-leak and lifetime fixes following issue #239: AOP proxies release their targets, Spring.Web stops pinning the first factory and page, and the dead disposable-object store is gone (#391, #396, #398)
* LogExceptionHandler logs again (#389) and the expression language evaluates suffixed integer literals such as `5L` (#395)
* Package validation against the previous release, and a README for every package

Please refer to the [GitHub release](https://github.com/spring-projects/spring-net/releases/tag/v4.0.0) for the full list of changes.
